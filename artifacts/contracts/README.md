# contracts/ — THE LAW of the DELIVERABLES (one subdir per member)

**Scope (L25): these docs describe the deliverable Loopstrap builds — never Loopstrap itself.** Loopstrap's own law is the dev-lane corpus (`methods/` · `instance/` · `registers/`), evolving by register ruling; no document here names or governs the engine's stations, runs, update vehicles, or interface. Every member instantiated on Loopstrap brings its own document set of this class — one lexicon + contract set per deliverable, the member's launch key.

Each member's ratified set lands in `contracts/<member>/`, by the owner's hand only: the **triad** — lexicon · system contracts · experience spec — plus the machine exports (clause-index, term-export, parties, docs-manifest), all per `../methods/deliverable-docs-standard.md` (L26; lexicon first, authoritative over the contracts). TO AUTHOR. Until ratification every member is spec-less: read-only posture, no code work, refusal on any implementation dispatch. Consumers cite these files by path + content hash. **Drafting requirements (L24, L8):** stable clause ids (an amended clause keeps its id; per-clause delta log — supersede, never renumber), a machine-readable clause index, and the lexicon's term-export file.
